# brain 条目格式

一个项目一条。维度缺就省略，不写空项。每条正文不超过 25 行。

## 标题行（必须）

```
## <YYYY-MM-DD HH:MM> · <日结|手动> | 项目：<项目id> | 来源：<机器>/<agent>[ | 会话：<会话id前8位>]
```

- 时间：写入时的本地时间。
- 类型：定时任务写「日结」，用户让你记写「手动」。
- 项目 id：小写字母、数字、连字符。确定顺序：用户在会话里说过的项目名（经 MAP 别名换成正式 id）→ MAP 目录映射 → 已有项目里的同一件事 → 都没有时，条目里有下一步、阻塞或假设（事情还没完）才按内容总结一个新 id，写成「项目：<id>（新）· <一句话说明>」；一次就做完的事（约会议室、写一段评价、装个软件）写「项目：misc」，「做了」开头点明是什么事。不问用户。
- 来源：`<机器>/claude-code`、`<机器>/codex`、`<机器>/hermes:<profile>`。
- 没有正文的特殊标题：
  - `## <时间> · 日结 | 无项目工作 | 来源：<机器>/<agent>`
  - `## <时间> · 日结 | 会话记录不可读：<原因> | 来源：<机器>/<agent>`
  - `## <时间> · 日结 | 日结失败：<profile>：<原因> | 来源：<机器>/hermes:<profile>`

## 正文维度（按需，每项一行，以「- 维度：」开头）

- 做了：具体完成的动作。
- 决定：选了什么；原因：…；未选：…
- 假设：待验证的判断（验证方法：…；到期：YYYY-MM-DD，缺省 30 天）
- 下一步：可执行动作，不写「继续完善」。
- 阻塞/未解决：等谁、缺什么。
- 产物：一个产物一行，可写多行。先核实再写，并写明核实方式。本机文件必须先运行 brain_verify.py，会话记录、ls、摘要列出都不算核实；brain_write 会拒收没写 brain_verify 或路径不存在的 [文件] 行。四种写法：
  - `- 产物：[文件] <标题> | artifacts/<项目>/<文件名> | md5 <前12位> · <大小> | 原位置 <机器>:<路径>（<id>；brain_store 复制并回读 md5 核实）` ← 已入产物库（brain_store.py 会自动生成这一行）
  - `- 产物：[文件] <标题> | <机器>:<路径>（未入库；brain_verify 核实 <大小> <修改时间>）` ← 只记指针，用户以后说「存一下」再入库
  - `- 产物：[链接] <标题> | <URL>` ← 在线文档 / Figma / Claude Artifact 等云端内容，必须带 URL，只写标题找不回
  - `- 产物：[代码] <仓库> @ <commit>（git log 核实）` ← 代码只记仓库与 commit，不复制文件
- 更正：旧「…」→ 新「…」；原因：…；根因：…
- 经验：场景 … / 做法 … / 结果 … / 适用 … / 不适用 …
- 偏好：「用户原话」（日期；范围：全局、全局·<哪类输出> 或项目 id）。只记以后都适用的话：
  - 原话带「以后、后续、每次、所有、默认、一律、不要再、别再」或用户说了「记住」：来源等级标用户告知。
  - 没有这些词、但看得出是长期习惯或本项目一直要守的口径和要求：照写，来源等级标推断。
  - 选了某个方案（选 A 不选 B）：不写偏好，写成「决定」。
  - 只管这一次的指令（「先帮我把目标写了」「这次新建一封邮件」）：都不写。
- skill 反馈：skill:<name>@<版本> 有效|部分有效|无效：原因
- 来源等级：哪些是工具实测、哪些是用户告知、哪些是推断

## 示例

```
## 2026-09-13 19:00 · 日结 | 项目：weekly-report | 来源：work-mac/claude-code | 会话：d299f38d
- 做了：完成配网章节的数据核对；修复周环比公式
- 决定：周报只发页面链接不发截图；原因：老板在手机上看链接更方便；未选：截图版
- 假设：崩溃率下降与 3.2.1 灰度有关（验证方法：对比 3.2.0 与 3.2.1 分版本数据；到期：2026-09-20）
- 下一步：把 W37 数据导入模板并生成预览
- 阻塞/未解决：项目表 9 月 12 日后的数据未更新，等同事补
- 产物：[代码] weekly-report @ 3f2a9c1（已推送 origin/main；git status -sb 核实）
- 产物：[文件] W36 周报预览 | work-mac:~/projects/weekly-report/out/W36.html（未入库；brain_verify 核实 48.2KB 09-13 18:40）
- 更正：旧「主力版本固定为 3.1.0」→ 新「按全部活跃版本总量重算」；原因：09-12 与老板确认口径；根因：沿用上季度口径没复核
- 经验：场景 周报崩溃率口径 / 做法 聚合全部活跃版本按总量重算 / 结果 与业务侧数字对齐 / 适用 分版本指标 / 不适用 单版本灰度评估
- 偏好：「以后周报只要链接，别发截图」（2026-09-13；范围：weekly-report）
- 来源等级：做了、产物为工具实测；决定、偏好为用户告知；假设为推断
```
