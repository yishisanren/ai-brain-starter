# 周总结模式（每周一 12:30）

读取：上周一至周日的 `_meta/runs/*`、各项目 STATUS / DECISIONS / HYPOTHESES / LESSONS / history、`lessons/CORRECTIONS.md`、`_meta/PENDING.md`、`skills/REGISTRY.md`、上一份 `_meta/weekly/*`。

输出：`_meta/weekly/<YYYY-Www>.md`，按覆盖周命名：上周一所在的 ISO 周，不是生成日所在周（例如 10 月 12 日周一生成的文件覆盖 10 月 5 日至 11 日，叫 `2026-W41.md`）；把「给你的一页」作为最终回复，写在定时任务会话里。

## 文件结构

```markdown
---
title: 周总结 <YYYY-Www>
period: <周一日期> 至 <周日日期>
generated: <时间>
---
# 周总结 · <YYYY-Www>

## 给你的一页
1. 本周最值得记的事：每个活跃项目一句，只写真实产物与完成的事。
2. 反复出现的模式：同类阻塞第二次以上；同类更正第二次以上；同一项目连续两周「下一步」没变（停滞）；同一决定被推翻又恢复。每条注明日期与来源。
3. 上周说要做的做了吗：上周各项目 STATUS「下一步」对照本周「做了」；完成率（完成数 / 上周下一步总数）；未做清单，连续未做的标「连续 N 周」。
4. 下周聚焦：每个活跃项目一条；全局只选一件事。
5. 值得推演的决定：本周新增的决定与下一步里，不可逆、影响一个月以上、或连续三天被提到的；到期待回填的假设，逐条问「后来怎么样了」。
6. 未选之路回放：DECISIONS 里满 3 个月的决定的「未选」路线；先判断情境是否仍相关，不相关不列。
7. 待你处理：PENDING 未处理的 D 项按类型汇总；本周自动创建的新项目（可回复「改名 旧→新」或「合并 A→B」）；本周日汇总自动转 paused / done 的项目，一行列 id；待确认偏好 P 项（可回复「确认 P-…」或「作废 P-…」）；Skill 草案。
8. 记忆健康：各机器各 agent 本周有日结的天数；缺失的机器与 agent；Hermes 各 profile 日结失败次数；本周新增偏差档案数；Skill 反馈汇总。
9. 进步：上周列出的问题本周解决了的，单列。

## 明细
- 各项目本周变化表：做了 / 决定 / 假设 / 下一步 / 阻塞
- 本周新增经验（id、标签、状态）
- 本周新增偏差档案（B 项）
- 本周新建项目与合并建议
```

## 规则

- 每个「模式」「停滞」判断必须引用具体条目日期与来源。
- 没有样本的项写「无」，不写 0% 或 100%。第一份周总结没有上周基线：第 3、9 节写「无基线（首份）」，停滞判断写「无」。
- 未处理的待裁定项只在周总结里集中重提，不单独再发。
- 「活跃项目」= INDEX 里状态为 active 的项目；`_merged-*` 目录和状态为 done / 已停用 / 未迁移的不算。活跃项目超过 8 个时，「给你的一页」第 1、4 节只列本周有日结条目的项目，其余放进明细表。
- 记忆健康的统计口径：只统计生成时刻已经过了 19:00 日结窗口的日期；MAP「机器」表里 hostname 仍为「待填」的机器写「未接入」，不算缺失。
- Hermes profile 日结失败 = 该 profile 当天 inbox 里是「日结失败」行，或其他 profile 有条目而它没有；条目正文里记录的业务 cron 失败不算日结失败。
- 周中手动生成时按「截至生成时刻」出报，frontmatter 加 `data_cutoff`。
