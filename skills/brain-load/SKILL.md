# brain-load

脚本在本技能目录的 `scripts/` 下，下文写作 `<技能目录>`（装好后在 `~/.agents/skills/brain-load`，Claude Code 经软链接也能从 `~/.claude/skills/brain-load` 找到）。Windows 用 `python` 代替 `python3`。

## 步骤

1. 运行脚本：

   ```
   python3 -B <技能目录>/scripts/brain_load.py --cwd "<当前工作目录>" [--project "<用户说的项目名或 id>"]
   ```

   用户点名了项目就加 `--project`。脚本报错（找不到根目录、本机未登记）时把错误原文告诉用户，不猜路径。

2. 根据脚本输出写开工简报，不超过 40 行：

   ```
   开工简报 · <项目id> · STATUS 生成于 <时间或「尚未汇总」>
   自动运行提醒：（脚本输出有「自动运行提醒」时照实写，并说怎么补跑）
   目标：
   现状：
   下一步：（编号，注明来源与日期）
   阻塞：
   已更正（不要再用）：
   到期待回填的假设：
   尚未汇总的最近条目：（时间 · 来源 · 一句话）
   相关偏好：（3 条以内）
   这个项目别再犯：（3 条以内，从「本项目经验」「本项目更早的偏差」里挑和本次任务相关的，一条一句话）
   本项目产物：（3 条以内，id · 标题；用户要就用 brain-find 取）
   待你裁定：
   ```

   没有内容的行删掉。

3. 输出「项目：未绑定」时：
   - 用户只说「开工」「接着上次做」、没说做什么：取「最近有记录的项目」第一行，加 `--project <它>` 重跑一次，按步骤 2 写简报，第一行注明「按最近一条记录接上」。用户说不是这个，再换。
   - 用户说了要做的新事：一句话说明本次尚未绑定项目，工作内容明确后由 brain-note 按内容命名；附脚本列出的最近项目。不追问。
4. 然后开始工作。不读 history，不复述整份 STATUS。

## 约束

- 只读，不写任何文件。
- STATUS「已更正」段列出的旧结论视为失效。
- 标「尚未合并」的 inbox 条目比 STATUS 新，冲突时以它为准。
